# ActualForge 0.1.2

Released: 2026-10-02

ActualForge 0.1.2 extends the Airtable bridge so ChatGPT can work with the core financial data from the currently opened Actual budget.

## Highlights

- Exports Actual accounts, transactions, categories and schedules to the dedicated Airtable bridge.
- Adds **Airtable synchronisieren** directly to the ActualForge page, including on mobile.
- Large datasets are split into application batches and then into Airtable-safe 10-record upserts.
- Split transactions include `CountInTotals`; use `CountInTotals = true` when calculating financial totals to avoid counting split children twice.
- Deleted Actual records are mirrored with `Deleted = true` and `SyncState = ignored`.
- Finance-engine Airtable export from 0.1.1 remains available.

## Safety boundary

- Actual remains the authoritative store for original accounts and transactions.
- The finance-engine does not create a second persistent transaction database.
- Core export originates inside the opened Actual budget and traverses the authenticated ActualForge same-origin API.
- Airtable remains export/analysis-only. It cannot modify Actual data in this release.

## Using the core sync

With the Airtable variables already configured, open **ActualForge** in the web/PWA and choose **Airtable synchronisieren**.

The page shows the number of accounts, transactions, categories and schedules handed to the export queue. It then displays queue progress or an error state.

## Deployment

```bash

docker compose -f compose.release.yaml up -d
```

Images:

