# ActualForge 0.1.1

Released: 2026-10-02

ActualForge 0.1.1 adds an optional Airtable bridge for ChatGPT-assisted analysis while preserving ActualForge's local-first safety boundaries.

## Highlights

- Export-only Airtable synchronization for finance-engine data.
- Batched upserts with stable identifiers to avoid duplicate records.
- Sync logging, retry handling and startup/interval synchronization.
- Environment-based configuration for Docker and release deployments.
- Airtable bridge coverage for contracts, contract price history, payment chains, transaction links/splits, transfer matches, clarification cases, prediction entries, merchant mappings, recognition rules and credit-card profiles.
- Raw JSON is retained alongside mapped fields so new finance-engine fields are not silently lost.

## Safety boundary

- Airtable sync is disabled by default.
- The Airtable token is supplied only through deployment secrets/environment variables.
- Airtable is an analysis/export surface in 0.1.1.
- Airtable changes are not written back into ActualForge.
- Original Actual transactions remain authoritative and are not modified by the bridge.
- Full Actual account/category/transaction export is intentionally deferred until an explicit Actual application/API bridge exists.

## Deployment

Required Airtable settings in the untracked deployment `.env`:

```env
AIRTABLE_SYNC_ENABLED=true
AIRTABLE_TOKEN=pat_xxxxxxxxx
AIRTABLE_BASE_ID=appDhIt8N6IH2EM5J
AIRTABLE_SYNC_INTERVAL_MINUTES=15
```

Then deploy:

```bash
docker compose -f compose.release.yaml pull
docker compose -f compose.release.yaml up -d
```

Images:

```text
ghcr.io/tojollinor/actualforge:0.1.1
ghcr.io/tojollinor/actualforge-finance-engine:0.1.1
```
